# Oura Ring 4 — auth-key extraction

Gadgetbridge talks to the ring directly over BLE. To do this it needs the
16-byte AES key the ring was paired with during onboarding. The key is
generated by the official Oura mobile app and written to the ring once
per factory-reset over BLE in cleartext (opcode `0x24 SetAuthKey`).

Three ways to recover it, from easiest to hardest:

## 1. BLE pairing capture (no root, no jailbreak — recommended)

The official app writes the key to the ring during pairing as opcode
`0x24 SetAuthKey`. If you capture Bluetooth HCI traffic on the phone
while pairing, the cleartext key is in the snoop.

Steps:

1. **Factory-reset the ring** from the official Oura app
   (*Settings → Ring → Reset Ring*).
2. **Enable Bluetooth HCI snoop** on the phone:
   - Android: *Developer options → Enable Bluetooth HCI snoop log*.
     Toggle Bluetooth off and on so the next session starts captured.
   - iOS: install Apple's *Bluetooth Explorer* / *PacketLogger* profile
     and start a packet log.
3. **Pair the ring** in the official Oura app as you normally would.
4. **Pull the snoop file**:
   - Android: run `adb bugreport report.zip`, unzip, and find
     `FS/data/misc/bluetooth/logs/btsnoop_hci.log` (and `.log.last`).
   - iOS: PacketLogger → File → Save (`.pklg`).
5. **Run the extractor** that ships in the Gadgetbridge source tree at
   `app/src/test/resources/oura_protocol/oura/tools/extract_auth_key.py`:

       python extract_auth_key.py path/to/btsnoop_hci.log[.last]

   The script prints the 16-byte key in hex and self-verifies it against
   any handshakes captured in the same snoop. Paste those 32 hex
   characters into Gadgetbridge.

The cleartext window only opens during a factory-reset re-pair. A
bugreport captured at any other time will not contain the key.

iOS captures (`.pklg`) need to be converted to Android btsnoop format
first — `tcpdump -r capture.pklg -w capture.btsnoop` works, as does a
Wireshark "Export as btsnoop" save.

## 2. iOS iTunes backup

Decrypt the backup with the iCloud password, then read the
`ringconfiguration` table from
`/Applications/AppDomain-com.ouraring.oura/<USER_ID>/assa.sqlite`. The
`auth_key` column is the 16-byte blob.

## 3. Rooted Android device

Magisk-rooted phone:

    adb shell su -c 'sqlite3 /data/user/0/com.ouraring.oura/databases/<file> \
        "SELECT id, hex(auth_key) FROM ringconfiguration;"'

`adb backup` is typically disabled by the Oura app's manifest, so on
non-rooted production phones this path is blocked.

## How to paste the key into Gadgetbridge

1. Pair (or "discover") the ring in Gadgetbridge.
2. When prompted for the auth key, paste 32 hex characters
   (case-insensitive; spaces and `:` separators are allowed).
3. Save. The ring should connect within a few seconds.

If the ring rejects the key with "Auth rejected", verify you copied the
right row — the Oura app keeps multiple `ringconfiguration` entries when
re-paired. With a fresh BLE capture, run `extract_auth_key.py` again to
confirm against the most recent `0x24` write.
